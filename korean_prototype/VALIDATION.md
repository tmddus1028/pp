## 자동 검증 범위

- 한국 청구항 번호, 범위, 다중·전이 종속관계, 삭제항, 누락 부모·순환 오류.
- 거절표의 대상 청구항과 법조항만 추출. 일반 안내 법조항·인용발명의 청구항은 제외.
- 모호한 복수 거절 본문 연결은 오류로 처리.
- PDFium 텍스트 추출 fallback, 빈 파일·손상 PDF·출원번호 불일치·XML DTD 오류.
- API 문서/health, multipart 요청, 원본 해시 불일치 감지, Azure 미설정 오류.
- UI 최초 무선택, 원문 이동 시 Claim·요약 유지, 새 분석에서 상태 초기화.
- 같은 파일명의 서로 다른 PDF를 document_id로 구분해 정확한 bytes 표시.
- Azure 명시적 요청, 문맥 상한, 원문 위치, 알 수 없는 근거 ID 거절,
  타임아웃·응답 오류 및 실제 SDK 구조화된 응답 처리(MockTransport).
- PDF 추출에서 문단번호가 줄 앞/끝에 있는 경우 모두 첫 문장 보존 및 다음 문단 제외.

## 브라우저 검증

Microsoft Edge headless, 실행 주소 http://127.0.0.1:8502.

- 실제 사례 분석과 청구항·거절·인용발명 표시.
- OA XML 근거 선택 후 Claim 선택과 1 / 1 / 0 / 3 요약 유지.
- 청구항 원문으로 돌아가면 실제 PDF 3쪽 미리보기.
- 1920 / 1440 / 1280 / 1024px에서 원문 텍스트 자연스러운 줄바꿈.
- 텍스트 폭은 각각 약 1308 / 948 / 788 / 532px로 부모 텍스트 영역 전체를 사용.
- 실제 파일 업로드 후에도 청구항·거절·인용문헌 값이 일치하고 다시 Claim을 선택할 수 있음.
- 반복 재분석 때 같은 widget ID를 재사용해 화면 선택과 서버 상태가 어긋나는 문제를
  실제 브라우저에서 발견했다. 성공한 분석 회차별 selector key로 분리한 뒤 재검증하여 통과했다.

`scripts/browser_smoke.py`는 추가로 재분석 후 선택 초기화와 실제 파일 업로드를 검사한다.
최종 실행 결과는 `artifacts/browser_checks.json`, 화면은
`artifacts/korean-claim-review.png`, `artifacts/korean-pdf-page3.png`에 저장한다.

## 검증하지 않은 항목

- **실제 Azure 클라우드 호출과 생성 내용의 정확도:** 자격증명으로 호출하지 않았음.
  연결 코드는 mock SDK/HTTP 응답으로만 검사했으며 실제 LLM 분석 완료라고 표시하지 않는다.
- **한국 OA 원본 PDF:** 공식 OPD 링크는 찾았지만 CAPTCHA로 원본 파일 미확보.
- **한국 스캔 OCR:** 첫 프로토타입에서 미구현. 입력할 수 있다고 표시하지 않는다.
- **여러 실제 한국 사건의 일반화 성능:** 현재 실제 문서 한 쌍만 검증.
- **모든 XML 변형 및 복잡한 보정·허용·철회 사건:** 추가 자료 확보 및 구현 필요.
- **출원 당시 제출 파일의 완전한 버전 인증:** 공개 청구항·OA 구성 일치 및 공식 이력은
  확인했지만 모든 제출·보정 원문 파일을 확보한 것은 아님.

이는 한국어 시제품의 구현·회귀 검증이며 전체 한국 특허 문서나 법률 판단의 정확도를
입증한 결과가 아니다.
